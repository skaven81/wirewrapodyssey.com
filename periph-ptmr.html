Peripherals: Programmable Timer

Overview

The DS1511Y RTC already gives the Odyssey one configurable periodic interrupt (see RTC & Timer), but that's one timer, running off one clock, doing one job at a time. Its watchdog timer can be programmed down to hundredths of a second, which is certainly useful, but not particularly high precision. To get real high-precision one-shot delays, jitter-free periodic interrupts, cycle-accurate profiling, and a tone generator for a piezo speaker - all independently, all live at once - I added a second timer peripheral built around an 82C54-compatible programmable interval timer, the same chip family that did double duty as the system timer in the original IBM PC. It has three independent 16-bit countdown on one chip, each with its own selectable clock source, all sharing a single interrupt line (IRQ2) and a single block of address space, 0xC400-0xC4FF. I number the three counters Timer 1, 2, and 3, to keep them distinct from the RTC's own interrupt, which I call Timer 0.

Slicing Up 0xC400-0xC4FF

The 82C54 itself only needs four addresses: three 8-bit counter registers and one control/read-back register, mapped straight through at 0xC480-0xC482 and 0xC483. Everything else in the page is Odyssey-side glue, kept to as few extra chips as I could manage.

Clock source selection isn't part of the 82C54 at all — the chip just exposes bare CLK pins — so I built an external 8-bit register at 0xC440 that picks one of four clock sources (a 1.8432MHz oscillator, the 32.768kHz RTC crystal, a 1.000MHz oscillator, or the CPU's own system clock) independently per timer, two bits apiece across the low six bits. The top two bits of that same register are the tone-select field, described below.

The IRQ side needed a signal the 82C54 doesn't provide either — OUT is just a level, not an interrupt request. Rather than burn a chip decoding a dedicated "clear IRQ" address per timer, I decoded the clear signals directly off address lines A5, A4, and A3 within the 0xC400-0xC4FF page, independent of every other address decode in that range. That means those three bits can be ORed onto any other address in the page — a counter read, a control word write, even a bare no-op access — and the corresponding timer's IRQ latch clears as a side effect of that same bus cycle, for free. 0xC4A0, for example, is just "access Counter 1" (0xC480) OR'd with "clear Timer 1's latch" (0x0020) landing on one address. It costs nothing extra in hardware or cycles, and it means an ISR reloading a counter can clear that timer's own latch in the very same instruction.

Reading which timer(s) actually fired takes one more address: 0xC404 returns all three latch bits in a single byte (bit 5 = Timer 1, bit 6 = Timer 2, bit 7 = Timer 3), so the ISR can snapshot the whole peripheral's state in one read instead of polling three separate status lines.

Interrupt Latches, and Excluding a Timer for Tone Generation

The 82C54's OUT pins toggle in whatever pattern their mode dictates:

  • Mode 0: OUT goes high on terminal count, stays there
  • Mode 1: Hardware triggered one-shot timer, requires GATE signal
  • Mode 2: Rate generator: OUT pulses high on terminal count, resets itself
  • Mode 3: Square wave generator: OUT goes high after ~50% of the count, then low again at terminal count
  • Mode 4: Software triggered strobe: OUT goes low for one clock pulse at terminal count
  • Mode 5: Hardware triggered strobe, same as mode 4 but requires GATE signal
The modes that require a GATE signal are not useful for the Odyssey, and even the modes used in the Odyssey (modes 0, 2, and 3) are useless as level-triggered interrupt sources on their own. So each timer's OUT feeds the CLK input of a dedicated 74HC74 flip-flop with D tied to Vcc: any rising edge on OUT latches a 1 into Q, and it stays there until software clears it via the address trick noted above. The "clear latch" address lines are routed through simple combinatorial gates so that when set, and in the 0xc4 range, and the system clock strobes, the asynchronous clear signal is asserted for the D-FF that is to be cleared. All three output Qs are then used to feed a 3-inputx NOR gate, whose output is the Odyssey's active-low /IRQ2 line. If any of the three timers have completed terminal count, their latch is set and IRQ2 is asserted.

Adding tone generation meant inserting one more piece into that path. Each Q now feeds a 74HC08 AND gate before the NOR, and the second input of each AND gate comes from a 74HC139 2-to-4 decoder driven by the tone-select bits at 0xC440[7:6]. The decoder's four active-low outputs are /Y0 (tone off), /Y1, /Y2, and /Y3, one per timer. Normally those three AND-gate inputs sit high and the gates are transparent, so the circuit behaves exactly as it did before I added tone generation. But select a timer for tone, and its /Yn drops low, forcing that one AND gate's output low regardless of what its latch is doing — that timer's interrupt simply never reaches the NOR gate, no matter how many edges OUT produces.

That's what makes Mode 3 usable at all. Mode 3 turns a counter into a free-running square wave, exactly what you want feeding a piezo speaker, but at audio frequencies it would otherwise fire the latch (and IRQ2) thousands of times a second. With the AND-gate exclusion in place, whichever timer is selected for tone can run Mode 3 freely while the other two keep interrupting normally. The same two select bits also drive a 74HC153 mux that routes the chosen timer's raw OUT — tapped before the flip-flop, so it's still the live square wave, not a latched edge — to a 2N2222 transistor through a 1K base resistor, switching a piezo speaker wired with a 330Ω series resistor. Selecting and excluding happen from the same two bits in the same register write, so there's no separate masking step required in software.
